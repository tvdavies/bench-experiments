An LLM benchmark where thinking costs time

Can a model land a spacecraft when the world won't wait for it to think?

Each model flies a small lander through gusty wind onto a pad. We fly every scenario twice. Paused: the world freezes while the model reasons. Live: every output token burns ms of flight time while the previous command keeps running. The gap between the two is the thinking tax.

Results

Mean score out of 100 across seeded scenarios. A safe landing scores 70 or more; crashes earn partial credit for how close they came.

    Method

    Small, deterministic and provider-neutral. Code: tvdavies/bench-experiments.

    One protocol for every pilot

    Every pilot gets the same information: one JSON observation with the task, rules, vehicle, controls, instrument readings and the last 10 readings. Every pilot answers the same two questions, word for word, and chooses from the same menus: throttle 0 to 1 in 0.1 steps, lateral −1 to 1 in 0.25 steps. This applies to chat models, Jev and the hand-written controllers alike. Chat models get the observation as a message and answer through a tool; Jev gets it as state and answers through choice questions. Nothing else is asked, and automated tests check that every pilot receives the same observation and menus.

    The sim

    A 2D point-mass lander. Gravity 1.6–3.7 m/s², a main engine giving up to 2g, lateral thrusters giving ±1.5 m/s², and 45 units of fuel. Wind is a random process with gusts and a noisy wind reading. A safe landing needs |vy| ≤ 2, |vx| ≤ 1 and to be within 15 m of the pad. Every pilot on a seed faces the same air.

    The clocks

    Paused: the world waits, and each command is held for s. Live: each output token, reasoning included, costs ms (about tokens per second), and the previous command keeps running meanwhile. The rule and the previous decision's cost are part of the observation. No pilot is told to be brief.

    Engine failure

    In the engine-failure set the main engine silently drops to 75% thrust partway down. No pilot is told. A controller that trusts the spec sheet crashes almost every time, while an adaptive one survives about half. Descending slowly isn't a free fix either, because the fuel runs out.

    Scoring

    A safe landing on the pad scores 70, plus up to 15 for fuel left and up to 15 for centring. Any other touchdown scores up to 50, decaying with how far outside the limits it was. A timeout scores 0. Episodes where the model API failed are dropped and not scored. Unusable answers count against the pilot, and the previous command is held.

    Baselines

    A 20-line P controller and a PI controller see the same readings at the same command rate, decide instantly, and are rounded to the same menus. Do nothing is the floor. If a model can't beat the PI controller, it isn't flying well.

    Caveats

    Five seeds per set, so treat small gaps as noise. Models are reached through one gateway with default settings. Jev · assessment framing is a side experiment that deliberately breaks the protocol: it gets extra derived readings and is asked "is the descent too fast or too slow?" rather than to choose a throttle. It's shown to illustrate how much framing changes Jev's behaviour, and is not ranked. Fable 5.2 could not be reached through the gateway.
